# Guino v0.1.0 — draft release notes

**Unpublished release candidate.** Package, binary and container-image
publication and the required native Linux CI checks remain release gates.

Guino is local infrastructure for AI agents, continuing the open-source Den
sandbox runtime under a new project identity. Its original Git history,
authorship, tags and applicable licenses are preserved. The current migration is
a history-preserving copy of `us/den`, not a completed GitHub transfer or a claim
that the upstream maintainers have renamed their project.

## Changes

- `guino` CLI, `github.com/tmls-ai/guino` Go module, `@tmls-ai/guino` TypeScript
  SDK and `guino` Python SDK naming.
- `guino.yaml` discovery and `GUINO_*` environment settings. Guino 0.1.x retains
  deprecated Den config/env aliases and SDK imports, with documented precedence.
- Existing databases, ownership labels, volumes and snapshot identities remain
  compatible; these stored identifiers intentionally retain their Den names.
- Source-based local quickstart, MCP setup for Claude Code, Codex, Cursor and
  custom clients, and updated security/operations documentation.
- Checksum-verified release installer, release guards, SDK/build CI, security
  scanning configuration and contributor templates.
- Fixed Alpine file listing used by S3 cleanup and normalized the object-key
  separator when uploading cleanup files. Regression checks verify uploaded
  contents rather than treating a logged cleanup error as a passing result.

The Docker runtime, REST API, WebSocket execution, snapshots, volumes, S3,
resource limits, automatic cleanup and embedded dashboard remain local and
self-hosted. No cloud account, billing service or placeholder cloud commands
were introduced.

## Upgrade

Read the [migration guide](../migration.md) before sharing an existing Den state
directory with Guino. Stop the previous runtime, back up its database and volumes,
then install Guino. Keep source-install instructions as the primary onboarding
until released packages and archives have been checked in a fresh environment.

Runtime licensing remains AGPL-3.0; inherited SDK license metadata is unchanged.
See the repository license and the individual package notices.
